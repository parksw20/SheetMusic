# 기능 분석과 로드맵

심플리피아노의 기능을 난이도별로 나누고, 단계별로 구현 계획을 세운 문서입니다.

## 기능별 난이도

| 난이도 | 기능 | 방법 |
|---|---|---|
| 🟢 쉬움 | 악보 렌더링과 커서 | OpenSheetMusicDisplay + MusicXML |
| 🟢 쉬움 | 악보 재생, 템포, 한 손 연습 | Tone.js, 악보 데이터 필터링 |
| 🟢 쉬움 | 곡 라이브러리 | 저작권 만료 곡 (Mutopia, IMSLP, MuseScore 공개 도메인) |
| 🟡 보통 | MIDI 키보드 입력 | Web MIDI API (iOS Safari는 미지원이라 네이티브 래핑 필요) |
| 🟡 보통 | 채점 엔진, 대기 모드/박자 모드 | 기대 음과 입력 음을 시간 허용 오차 안에서 매칭 |
| 🟡 보통 | 떨어지는 노트 화면 | Canvas/WebGL |
| 🟡 보통 | 레슨 커리큘럼, 반주 트랙 | JSON 레슨 정의, 반주 파트 별도 재생 |
| 🔴 어려움 | 마이크로 어쿠스틱 피아노 인식 | 단선율은 음높이 검출(YIN), 화음은 "예상 음 검증" 방식 |
| ⚫ 보류 | 인기곡 편곡 | 저작권 라이선스 필요 |
| ⚫ 보류 | 악보 사진 인식(OMR), 구독 결제 | 제품 검증 이후 |

### 마이크 인식 접근법

앱은 지금 어떤 음이 나와야 하는지 이미 압니다. 그래서 임의의 소리를 악보로 받아 적는 대신 **"나와야 할 음이 들렸는가"만 확인**합니다.

1. AudioWorklet에서 마이크 입력을 받아 소리의 시작(onset)을 검출합니다.
2. 그 시점의 크로마/CQT 스펙트럼에서 예상 음들의 에너지를 비교합니다.
3. 배음 때문에 생기는 옥타브 오인식과 주변 소음은 임계값을 조정해 처리하고, 반주는 헤드폰 사용을 권장하거나 판정에서 제외합니다.

## iPad 사용 시 입력 방식

주 사용 기기는 iPad이고, 화면 건반은 쓰지 않습니다. 그런데 iPad Safari는 Web MIDI를 지원하지 않습니다. 그래서 iPad에서 실제 피아노 연주를 받으려면 다음 둘 중 하나가 필요합니다.

- **마이크 인식(3단계)**: 추가 장비 없이 어쿠스틱/디지털 피아노 소리를 인식합니다. iPad에서는 이것이 우선순위가 가장 높습니다.
- **네이티브 래핑(Capacitor) + CoreMIDI 플러그인**: USB/블루투스 MIDI 키보드를 연결할 수 있습니다.

## 단계별 계획

- [x] **1단계 MVP**: MusicXML 불러오기, 악보 표시와 재생, 화면/컴퓨터 키보드, MIDI 입력, 대기 모드, 채점
- [ ] **2단계 연습 도구**: 박자 모드(템포에 맞춰 흘러가며 타이밍 채점), 구간 반복, 떨어지는 노트 화면, 메트로놈, 곡 20~30개
- [ ] **3단계 마이크 인식**: 단선율 인식 → 예상 음 검증 방식의 화음 인식 (2단계와 병행해서 프로토타입 먼저)
- [ ] **4단계 커리큘럼**: 레슨 구조, 진도, 연속 학습일, 업적
- [ ] **5단계 확장**: 계정과 동기화, PWA/Capacitor 앱 배포, 반주 트랙, 구독

## 기술 스택

| 영역 | 선택 |
|---|---|
| 프론트엔드 | React + TypeScript + Vite |
| 악보 | OpenSheetMusicDisplay (MusicXML) |
| 소리 | Tone.js (나중에 피아노 샘플로 교체 예정) |
| 입력 | Web MIDI API, 컴퓨터 키보드, 포인터 이벤트 → 이후 마이크(AudioWorklet) |
| 저장 | localStorage → 이후 Supabase/Firebase |
| 앱 배포 | PWA → Capacitor (iOS MIDI는 네이티브 플러그인) |
