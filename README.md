# SheetMusic

심플리피아노(Simply Piano) 같은 **피아노 악보 연습 앱**입니다. 현재는 1단계 MVP로, **iPad**(가로/세로)에서 악보를 크게 보는 것을 기준으로 화면을 구성했습니다.

## 기능

화면 구성
- **상단 막대**: 왼쪽에 로고(누르면 처음 화면), 가운데에 곡 제목, 오른쪽 위에 **설정(톱니바퀴)**. 어느 화면에서든 같은 자리에 있다
- **처음 화면**: 난이도 콤보박스(마지막에 고른 난이도를 기억) + 곡 카드. 한 화면에 카드 5.5장이 보이고 손가락으로 좌우로 넘긴다. 카드마다 곡에 맞는 그림
- **연습 화면**: 왼쪽에 `연습 시작`·`듣기`·`집중 연습`·연습 방식, 오른쪽에 템포(매우 느림 60% · 느림 80% · 보통 100% · 빠름 120% · 매우 빠름 140%)
  - 연습 방식 **기다리기**: 맞는 음을 칠 때까지 기다렸다가 다음으로
  - 연습 방식 **박자 맞추기**: 한 마디를 세고(딱딱 소리) 막대가 템포대로 흐른다. 음마다 제때(±0.25초) 쳤는지 보고, 안 치면 놓침으로 센다(`src/engine/rhythm.ts`). 마이크는 인식이 늦게 끝나도 친 순간의 시각으로 판정한다
  - **듣기**는 실제 그랜드 피아노 녹음(Salamander Grand Piano, CC-BY)으로 재생하고, 오디오 시계에 맞춘 굵은 막대·지금 마디 칠하기·지금 울리는 음 빛내기로 어디를 연주하는지 보여 준다
  - 곡에 들어가면 **마이크가 자동으로 켜지고**, 곡에서 나오면 꺼진다 (상단 오른쪽에 `듣는 중` 표시와 입력 크기)
  - **친 음이 악보에 바로 보인다**: 맞으면 초록, 틀리면 빨강 음표가 그 자리 음높이에 잠깐 나타난다. 지나간 음은 초록색
  - **집중 연습**: 누른 뒤 악보에서 마디를 드래그해 구간을 고르면 그 구간만 반복한다. 화면 위아래 끝으로 끌면 악보가 스크롤된다
- **설정**: 연습할 손(양손/오른손/왼손), 손가락 번호 보기, 다음 음 이름 보기, 마이크 감도, 진단 정보, 음원으로 악보 만들기, MusicXML 가져오기, MIDI 건반

악보
- MusicXML 악보를 [OpenSheetMusicDisplay](https://opensheetmusicdisplay.org/)로 그린다. 한 줄 4마디, 곡 전체에서 모든 칸이 같은 너비(`src/score/grid.ts`)
- 배율은 iPad 세로 화면 폭에 4칸이 꽉 차는 값으로 자동. 가로 화면에서는 같은 배율로 4칸이 화면 폭을 가득 채운다
- **손가락 번호**: 곡을 만들 때 자동으로 붙인다(`assignFingering`, 오른손은 위·왼손은 아래). 엄지가 도나 솔에 있는 기본 자리(도 자리·솔 자리)를 되도록 지키고, 손 위치 이동이 가장 적은 번호를 고른다. 같은 음을 이어 칠 때는 같은 손가락. 설정 "왼손도 낮은 음부터 1번"을 켜면 왼손 번호를 뒤집어(1↔5, 2↔4) 도 1·솔 5로 보여 준다

음원으로 악보 만들기 (설정 → 악보 만들기)
- **음원 파일**(mp3, m4a, wav, 동영상, 20분까지): 들어 보며 시작·끝을 정하고 그 구간(최대 5분)만 옮긴다
- **유튜브 링크**: 시작·끝 시간을 정하면 그 구간을 재생하며 마이크로 받는다. 유튜브 소리는 보안상 앱이 직접 읽을 수 없어서 마이크가 필요하다
- **마이크 없이**: 아이패드 화면 기록(제어 센터)으로 유튜브 구간을 녹화 → 음원 파일에서 그 영상을 고른다 (유튜브 탭에 안내)
- Spotify 공식 Basic Pitch로 음을 찾고(`BasicPitch.evaluateModel` → `outputToNotesPoly`), 빠르기 추정 → 8분음표 격자(기본, 16분음표 선택 가능. 흔들림을 따라가는 위상 고정. 같은 칸에 떨어진 다른 타건은 센 쪽만) → 가운데 도 기준 양손 → 조표 추정 순으로 악보를 만든다(`src/transcribe/quantize.ts`)
- 배경 소음보다 충분히 큰 순간의 음만, 센 음의 옥타브 배음과 음높이가 흔들리는 소리(노래·비브라토, 반음 0.6 이상)는 빼서 잡음 음을 줄인다
- 결과 화면에서 박 나누기(8분/16분음표까지)와 음(모두 / 멜로디+베이스: 오른손 맨 위·왼손 맨 아래 음만)을 고를 수 있다
- 빽빽한 악보도 한 줄 4칸·같은 너비를 지키도록 배율을 0.35까지 줄인다
- 빠르기(BPM)와 박자(4/4, 3/4)는 결과 화면에서 바꿀 수 있다. 만든 악보는 **이 기기(브라우저)에만** 저장되고 난이도 목록의 `내 악보`에 나온다
- 유튜브 영상은 멀티스레드용 교차 출처 격리 상태에서는 넣을 수 없어서 `?nocoi` 주소의 유튜브 전용 화면으로 연다(`public/coi-serviceworker.js`)

채점과 입력
- 대기 모드: 맞는 음(화음은 모든 음)을 칠 때까지 기다렸다가 다음으로. 맞은 음, 틀린 음, 정확도, 별점(0~3), 곡별 최고 별점 저장
- 마이크는 한 번 받은 입력을 닫지 않고 다시 써서, 곡을 여러 번 드나들어도 권한을 한 번만 묻는다(iPad Safari는 닫았다 열면 다시 묻는다)
- 사람 목소리 거르기: 틀림 후보마다 원래 소리에서 배음 주파수를 위상 차이로 정밀하게 재서(0.03~0.18초, 센트 단위), 피아노처럼 음높이가 고정된 또렷한 음(12센트 이하)만 틀림으로 센다. 화음 속 음도 배음별로 잰다(`src/input/steadiness.ts`). 녹음으로 잰 값은 피아노 0.7~6.4센트, 말소리 16센트 이상
- 입력: **마이크**(iPad 기본), MIDI 건반(Web MIDI: Chrome, Edge. iPad Safari는 미지원), 외장 키보드(`A`~`;` 흰 건반, `W E T Y U O P` 검은 건반, `Z`/`X` 옥타브)
- iPad 홈 화면에 추가하면 주소창 없이 전체 화면으로 실행

## 실행

```bash
npm install
npm run dev      # 개발 서버 (http://localhost:5173)
npm run dev:ipad # iPad용 HTTPS 개발 서버 (같은 Wi-Fi에서 https://<PC IP>:5173 접속)
npm test         # 단위 테스트 (파서, 채점 엔진)
npm run build    # 타입 검사 + 프로덕션 빌드
```

## iPad에서 마이크로 연습하기

1. 배포 주소를 열거나, 개발 중이라면 PC에서 `npm run dev:ipad`를 실행하고, 표시되는 `Network` 주소(`https://192.168.x.x:5173`)를 iPad Safari로 엽니다.
2. (`dev:ipad`만 해당) 자체 서명 인증서라서 경고가 나옵니다. **세부사항 보기 → 이 웹 사이트 방문**을 누릅니다. 마이크는 HTTPS에서만 동작합니다.
3. `연습 시작`을 누르고 `🎤 마이크 켜기`를 누른 뒤 마이크 권한을 허용합니다.
4. iPad를 피아노 보면대에 두고 연주합니다. 레벨 막대가 움직이는지 확인하세요.

잘 안 잡히면 감도를 `높음`으로, 틀린 음이 너무 자주 나오면 `낮음`으로 바꿉니다.

### 마이크 인식 방식 (AI: Spotify 공식 basic-pitch-ts)

Spotify가 공개한 [basic-pitch-ts](https://github.com/spotify/basic-pitch-ts)(npm `@spotify/basic-pitch`, Apache 2.0)를 그대로 씁니다. 여러 음이 동시에 울리는 화음도 건반별로 구분합니다.

| 단계 | 사용하는 코드 |
|---|---|
| 모델 실행 | 공식 `BasicPitch.evaluateModel` (TensorFlow.js) |
| 음 추출 (시작 시간, 길이, 세기) | 공식 `outputToNotesPoly` → `noteFramesToTime` |
| 모델 파일 | 공식 패키지의 `model/` (빌드할 때 `scripts/copy-model.mjs`가 `public/models/`로 복사) |
| 마이크 수집, 22,050Hz 변환 | `src/input/mic.ts`, `src/input/resample.ts` |
| 별도 스레드 실행 | `src/input/aiWorker.ts`, `src/input/aiClient.ts` |
| 악보와 비교해 맞음/틀림 판정 | `src/input/onsets.ts` (앱 고유 로직, 단위 테스트 있음) |

1. 마이크 소리를 끊김 없이 모읍니다 (AudioWorklet).
2. 앞 분석이 끝나자마자 최근 1.5초를 공식 모델에 넣고, 공식 `outputToNotesPoly`로 음 목록을 받습니다 (타건 확률 기준 0.7). 공식 `evaluateModel`은 쓰지 않는 음높이 곡선까지 계산해 두 배 느려서, 모델 실행만 직접 합니다.
   - **빠른 확인**: 창 끝 0.17초는 모델이 뒤 소리를 못 봐서 공식 방식은 확정하지 않습니다. 이 구간에서 *지금 쳐야 할 음*의 타건 확률이 기준 이상이면 먼저 맞음으로 봅니다. 틀림은 확정될 때까지 기다립니다.
3. 창이 겹쳐 여러 번 나오는 같은 음은 한 번만 쓰고, 창 시작에 걸친 음(앞에서부터 울리던 음)은 버립니다.
4. 지금 쳐야 할 음이면 맞음, 아니면 세기 0.5 이상일 때만 틀림으로 봅니다. 화음이나 배음이 몇 ms 차이로 잡혀도 틀림으로 세지 않고, 앞 단계를 끝낸 타건으로 다음 단계를 미리 맞히지 않습니다.

분석은 **Web Worker**(별도 스레드)에서 돌아서 화면이 굳지 않습니다. AI는 앱을 열 때 백그라운드에서 미리 불러옵니다.

분석을 빠르게 하는 방법:

- **1.5초 창**: 공식 모델은 2초 소리를 받지만, 합성곱으로만 되어 있어 불러올 때 입력 길이 숫자만 바꾸면 가중치 그대로 1.5초를 분석합니다(약 25% 빠름). 모델 앞단(CQT)이 소리를 8번 절반으로 줄인 뒤 128칸 거울 여백을 붙이기 때문에 1.5초보다 짧게는 안 됩니다. 2초 창과 비교해 판정 구간의 타건 확률 차이는 0.02 이하입니다.
- **WebAssembly 멀티스레드**: GitHub Pages는 응답 헤더를 못 바꿔서 [coi-serviceworker](https://github.com/gzuidhof/coi-serviceworker)를 바탕으로 만든 `public/coi-serviceworker.js`로 교차 출처 격리를 켭니다(처음 한 번 페이지가 다시 열림). 스레드 수는 코어 수의 절반(최대 4)이고, 진단 줄에 `wasm×4`처럼 나옵니다. tfjs가 보조 스레드에 넘기는 코드가 압축 과정에서 깨져서 `vite.config.ts`의 `tfjsWasmThreadsFix`로 고칩니다.
- **WebGPU 자동 선택**: WebGPU가 되는 기기에서는 처음 불러올 때 WebAssembly와 WebGPU를 한 번씩 재 보고, 같은 음을 찾으면서 더 빠를 때만 WebGPU를 씁니다(진단 줄에 `webgpu`). iPad의 WebGL은 16비트 정밀도라 결과가 틀어질 수 있어 WebAssembly를 못 쓸 때만 씁니다.

조용한 방에서는 모델이 창마다 소리 크기를 맞추느라 잡음을 부풀려 가짜 타건을 만들기도 합니다. 그래서 최근 30초 중 가장 조용한 순간을 배경 소음으로 보고, 음이 시작된 순간의 소리가 그보다 10dB 이상 클 때만 인정합니다(`LevelGate`).

마이크를 켜면 악보 위에 진단 줄이 나옵니다. 인식이 안 될 때 어디서 막히는지 알 수 있습니다.

```
오디오 정상 · 48kHz · 수집 worklet 48k/초 · 입력 -40dB · AI worker/wasm×4 120ms · 최근 인식 2음
```

- `오디오`가 `정상`이 아니면 iPad가 오디오를 멈춘 상태입니다(마이크를 껐다 켜기).
- `수집 … 0k/초`면 소리가 안 들어옵니다. 1초 안에 안 들어오면 다른 수집 방식(`script`)으로 자동 전환합니다.
- `입력`이 -60dB 근처에서 안 움직이면 마이크 권한이나 입력 장치 문제입니다.
- `AI 준비 중`이 오래가면 모델을 받는 중이거나 실패한 것입니다.

사용 순서: `🎤 마이크 켜기` → 버튼이 `🎤 AI 인식 중`으로 바뀌면(모델 준비와 소리 수집, 몇 초 걸림) 연주를 시작합니다. 마이크 옆에는 들린 음이 표시되어 인식이 되는지 바로 볼 수 있습니다.

AI 모델을 불러오지 못하면 예전의 스펙트럼 방식(`src/input/pitch.ts`)으로 판정하고 버튼에 `(기본)`이 붙습니다.

실제 그랜드 피아노 녹음(Salamander Grand Piano)에 방 울림, 마이크 대역, 잡음을 섞어 브라우저에서 앱 전체를 실행한 결과:

| 녹음 | 맞음 | 틀림 |
|---|---|---|
| 작은 별 전곡 (양손 화음) | 65/65 | 0 |
| 징글벨 전곡 | 68/68 | 0 |
| 미뉴에트 G장조 전곡 (8분음표 0.35초 간격) | 83/83 | 0 |
| 도레미 (보통 / 작게 / 시끄러운 방) | 13/13 | 0 |
| 도레미 중간에 틀린 음 2번 | 13/13 | 2 (정확히 잡음) |
| 도레미, AudioWorklet이 안 되는 경우 (ScriptProcessor) | 13/13 | 0 |

지연(건반을 누른 뒤 판정까지)은 대략 분석 한 번 시간(진단 줄의 AI ms)의 1.5배입니다. PC 브라우저에서 분석 한 번이 약 130ms(v0.5.0은 약 380ms)라 약 0.2초입니다. 대기 모드에는 충분하지만, 템포에 맞춰 흘러가는 박자 모드를 만들면 이만큼 보정이 필요합니다.

알려진 한계:
- **스피커 소리**: 마이크를 켠 상태에서 `들어보기`를 하면 재생음이 마이크로 들어갑니다. 연습 중일 때만 판정하므로 채점에는 영향이 없습니다.
- **준비 시간**: 마이크를 켜고 몇 초 뒤부터 판정합니다. 그 전에 친 음은 세지 않습니다.

개발용 재생 테스트(평소에는 건너뜀):

```bash
# 실제 녹음 WAV를 AI 판정으로 재생 (단계는 MIDI 번호 배열)
AI_REPLAY_WAV=연주.wav AI_REPLAY_STEPS='[[60],[62],[64]]' npx vitest run src/input/aiReplay.test.ts
```

## 곡 추가하기

수록곡은 모두 저작권이 끝난 곡(전래곡·민요, 1900년 이전 작곡가)이거나 이 앱을 위해 직접 만든 연습곡(`SheetMusic 연습곡`)입니다.

| 난이도 | 내용 | 곡 |
|---|---|---|
| 입문 | 오른손 위주, 도 자리, 4분·2분음표 | 연습곡 15곡, 핫 크로스 번, 모든 오리들, 로디 아줌마, 달빛 아래서, 런던 다리, 프레르 자크, 맥도날드 할아버지, 양키 두들, 이 할아버지, 오 사랑스런 아우구스틴, 노를 저어라, 세 마리 눈먼 쥐, 거미가 줄을 타고, 오 수재너, 징글벨(1절), 성자의 행진, 떴다 떴다 비행기, 나비야 |
| 초급 | 양손(왼손은 긴 음), 3/4박자, 조표 1개 | 작은 별, 환희의 송가, 징글벨, 라르고(드보르자크), 클레멘타인, 브람스의 자장가, 놀라운 은혜, 벚꽃, 석별의 정, 고요한 밤, 기쁘다 구주 오셨네, 덱 더 홀스, 우리 모두 메리 크리스마스 |
| 중급 | 양손 모두 움직임, 16분음표, 조표 여러 개 | 미뉴에트 G장조, 환희의 송가(전곡), 코로베이니키, 종소리 캐럴, 그린슬리브스, 모차르트 교향곡 40번, 산왕의 궁전에서, 캐논, 엘리제를 위하여, 바흐 프렐류드 C장조, 월광 소나타 |

곡은 `scripts/generate-songs.mjs`(처음 7곡)와 `scripts/songs/level1~3.mjs`에 간단한 표기법으로 적은 뒤 (MusicXML 변환과 손가락 번호는 `src/score/buildMusicXml.ts`) `npm run songs`를 실행하면, `public/songs/`에 MusicXML과 곡 목록(`index.json`)이 만들어집니다.

```js
{ rh: 'E4:q. D4:e D4:h', lh: 'C3+E3+G3:w' }  // 음:길이, 화음은 +, 쉼표는 r, 점음표는 '.'
```

MuseScore 같은 악보 프로그램에서 MusicXML로 내보낸 파일을 `public/songs/`에 넣고 `index.json`에 등록해도 됩니다. 저작권이 만료된 곡만 사용하세요.

## 구조

```
src/
  score/grid.ts           한 줄 4칸, 같은 칸 너비를 위한 배율/마디 너비 계산 (테스트 있음)
  score/model.ts          내부 음표 모델 (NoteEvent, Step), 손 필터, 음 이름
  score/parseMusicXml.ts  MusicXML → NoteEvent[] (backup/forward, 화음, 붙임줄, 임시표)
  engine/practice.ts      대기 모드 상태 머신과 채점 (순수 함수, 테스트 있음)
  input/mic.ts            마이크 수집(AudioWorklet), AI/기본 방식 판정 연결
  input/basicPitch.ts     공식 basic-pitch-ts로 인식기 만들기 (WebAssembly 우선)
  input/aiWorker.ts       인식기를 Web Worker에서 실행
  input/aiClient.ts       Worker 불러오기/요청 (미리 불러오기, 실패 시 메인 스레드)
  input/onsets.ts         인식된 음 중복 제거, 맞음/틀림 판정 (순수 로직, 테스트 있음)
  input/resample.ts       마이크 샘플레이트 → 22,050Hz
  input/pitch.ts          기본 방식: 스펙트럼으로 기대 음 검증 (AI를 못 쓸 때)
  input/                  MIDI, 외장 키보드 입력 → 공통 NoteInput 이벤트
  audio/synth.ts          Tone.js 신스, 악보 재생
  components/             ScoreView(OSMD, 커서와 맞은 음 색칠), ResultPanel
  App.tsx                 화면 구성과 상태 연결
```

마이크, MIDI, 외장 키보드는 모두 같은 `NoteInput` 이벤트로 들어오고, 채점 엔진은 입력 방식을 모릅니다.

기능 분석과 이후 로드맵은 [docs/ROADMAP.md](docs/ROADMAP.md)에 있습니다.
